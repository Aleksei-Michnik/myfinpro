# 8.29 — Unified receipt intake (`ReceiptIntake`)

> Post-phase-8 consolidation (2026-09-26). Binding: `docs/ui-async-conventions.md`,
> `docs/image-handling.md` §4, `wiki/ui-design-system.md`, `wiki/receipts-and-llm.md`.

## 0. Why

Three surfaces offered "add a receipt" with three implementations:

| Surface                                        | Before                                                                                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `/receipts` (`ReceiptUploadZone` + page state) | drop zone, browse (multi) + camera, always-visible URL form, client-side type/size gate, multi-photo staging tray, PDF-per-receipt routing |
| `AttachReceiptDialog` (transaction detail)     | browse (multi → one receipt) + camera, always-visible URL field, type/size gate, no staging tray, "link existing" button                   |
| `TransactionFormDialog` → "From receipt"       | one raw `<input type="file">` (single file, **no camera button**, **no client-side gate**), collapsible URL row, "scan barcodes" button    |

On a phone the raw input opens the system document picker (Drive/Files) while the other two
surfaces offer the camera directly; three sets of wording (`receipts.upload.*`,
`receipts.attach.*`, `transactions.form.fromReceipt*`) said the same things. This iteration
replaces all three with **one component** and **one vocabulary**.

## 1. `components/receipt/ReceiptIntake.tsx` — THE receipt intake

**Purpose.** Everything a user can do to get a receipt into the extract → review → confirm
pipeline, in one block: photograph, browse, drop, paste a URL, plus the host's extra methods.
It owns the client-side gate, the multi-photo staging, the API call and its pending/error
state. Hosts only say _where the receipt goes_ and _what happens next_.

```ts
export type ReceiptIntakeTarget =
  | { kind: 'standalone' } // POST /receipts, /receipts/url
  | { kind: 'transaction'; transactionId: string }; // POST /transactions/:id/receipt{,-url}

export interface ReceiptIntakeProps {
  target: ReceiptIntakeTarget;
  /** Every successful create. Standalone "upload separately" passes several; transaction always one. */
  onCreated(receipts: ReceiptSummary[]): void;
  /** Host-offered extra methods — the button is rendered only when the handler is given. */
  onScanBarcodes?(): void;
  onLinkExisting?(): void;
  /** Host busy state (e.g. the surrounding form is submitting). Adds to the internal pending state. */
  disabled?: boolean;
  /** Per-surface intro line above the actions (already translated by the host). */
  hint?: string;
  /** data-testid prefix — see §1.5. */
  testIdPrefix: string;
}
```

Reuses (do not hand-roll): `FileCaptureButtons` (browse + camera, `ref → openPicker()`),
`RECEIPT_ACCEPT` / `validateUploadFiles` / `uploadRejectionMessage` (`lib/upload.ts`),
`RECEIPT_MAX_FILE_SIZE_BYTES` / `RECEIPT_MAX_FILES` (shared), `useReceipts()` (`uploadReceipt`,
`createFromUrl`, `attachFileToTransaction`, `attachUrlToTransaction`), `useAsyncOperation`
(`scope: 'control'`), `useToast`, `Button`, `ButtonSpinner`, `Input` (URL field, `size="sm"`),
`StagedPagesTray` (§2).

### 1.1 Layout (one layout, every surface)

A dashed-border block (`rounded-md border-2 border-dashed`, `border-gray-300 bg-gray-50`,
`dark:border-gray-600 dark:bg-gray-900/40`; while a drag hovers: `border-primary-500 bg-primary-50`
/ `dark:border-primary-400 dark:bg-primary-900/20`), `px-3 py-2`, `space-y-2`:

1. `hint` (when given) — `text-xs text-gray-600 dark:text-gray-300`.
2. **Action row** (`flex flex-wrap gap-2`), all `Button variant="outline" size="sm"`, in this
   order: `common.upload.browse` · `common.upload.camera` (the `FileCaptureButtons` pair, in the
   kit's own order — the same pair product pictures use) · `receipts.intake.url` (toggle,
   `aria-expanded`, `aria-controls` = the URL row id) · `receipts.intake.barcodes` (when
   `onScanBarcodes`) · `receipts.intake.linkExisting` (when `onLinkExisting`) · a `ButtonSpinner`
   while the op runs. Every button is disabled while pending or `disabled`.
3. `receipts.intake.dropHint` — `text-xs text-gray-500 dark:text-gray-400`, `hidden md:block`
   (drag-and-drop is a pointer-device affordance; phones never see the line).
4. **URL row** — rendered only while open: `flex gap-2`; `Input` (`type="url"`, `inputMode="url"`,
   `size="sm"`, `aria-label={t('urlLabel')}` — the kit `Input` has no visually-hidden label mode),
   placeholder `receipts.intake.urlPlaceholder`;
   submit `Button variant="secondary" size="sm"` `receipts.intake.urlSubmit`, disabled while the
   trimmed value is empty or pending. Opening the row moves focus into the field. **Enter** in the
   field submits the URL and `preventDefault()`s — it must never submit a host `<form>` (the
   transaction form wraps this block). Success clears and closes the row.
5. `StagedPagesTray` — rendered only while pages are staged.

Drag-and-drop targets the whole block (`onDragOver` → highlight + `preventDefault`,
`onDragLeave`, `onDrop` → same routing as a picker pick). Drops are ignored while pending or
`disabled`. The block is not itself a button (the action row carries the keyboard path), so no
`role="button"`/`tabIndex` on the container.

### 1.2 File routing (identical on every surface)

`handleFiles(raw, source: 'picker' | 'camera')` — drops count as `'picker'`:

1. Gate: `validateUploadFiles(raw, { accept: RECEIPT_ACCEPT, maxBytes: RECEIPT_MAX_FILE_SIZE_BYTES })`;
   every rejection → `addToast('error', uploadRejectionMessage(tUpload, rejection, RECEIPT_MAX_FILE_SIZE_BYTES))`.
2. Split accepted into `pdfs` (`type === 'application/pdf'`) and `images`.
3. PDFs:
   - `standalone`: each PDF is created as its own receipt, immediately (one op, sequential
     calls, `onCreated(all)` once at the end — as `uploadBatches` did).
   - `transaction`: a PDF is accepted only when it is the **only** file of the pick and the tray is
     empty (one transaction ↔ one receipt; the server rejects mixed page batches). Otherwise toast
     `receipts.intake.pdfAlone` and drop the PDFs; images continue.
4. Images: `source === 'picker'` **and** tray empty **and** exactly one image **and** no PDF in
   the same pick → create immediately. Otherwise stage them (append, in order) capped at
   `RECEIPT_MAX_FILES` with the `receipts.intake.tooManyPages` toast — camera shots always stage
   so a long receipt can be photographed page by page, and a pick that also carried a PDF stages
   its images because the one control-scope op is already busy with the PDF.

Creating: one `useAsyncOperation<ReceiptSummary[]>({ scope: 'control' })` for files **and**
URLs. `standalone` → `uploadReceipt(batch, signal)` / `createFromUrl(url, signal)`; `transaction` →
`attachFileToTransaction(id, batch, signal)` / `attachUrlToTransaction(id, url, signal)`. On
success: clear the tray (when it was the source), close the URL row, `onCreated(receipts)`.
Failure → `addToast('error', op.error.message || t('failedToast'))` (the existing
`useEffect` on `op.error` pattern, `reason !== 'aborted'`). No success toast here — hosts decide
(the receipts page toasts, the others navigate).

Tray actions: **Upload as one receipt** (`uploadAsOne`, count) → one create with all staged
files; **Upload as separate receipts** (`uploadSeparately`) → `standalone` only and only with ≥ 2
pages → one create per page in one op; **Clear**.

### 1.4 States

| State                | Behaviour                                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Idle                 | Action row enabled; no URL row; no tray.                                                                               |
| URL row open         | Field focused; Enter = submit; Esc does nothing special (the host dialog owns Esc).                                    |
| Staging              | Tray with thumbnails in order, remove per page, the two/three actions; more picks append.                              |
| Pending (op running) | Every button, input and the drop target disabled/ignored; `ButtonSpinner` in the action row; `aria-busy` on the block. |
| Host `disabled`      | Same as pending, without the spinner.                                                                                  |
| Error                | Toast (control-scope failure → toast, as the three surfaces already did); state preserved so the user can retry.       |
| RTL                  | Logical properties only (`start-*`/`end-*`, `ms-*`/`me-*`); thumbnails and the page number badge mirror correctly.     |
| Dark                 | Every colour above has its `dark:` pair.                                                                               |

## 2. `components/receipt/StagedPagesTray.tsx`

The tray moves out of `receipts-client.tsx` unchanged in behaviour (object-URL previews, revoke on
unmount, remove per page, actions) with these adjustments: strings from `receipts.intake.*`
(§4); `testIdPrefix` prop drives the ids of §1.5; `canUploadSeparately: boolean` decides whether
the second action renders (`standalone` with ≥ 2 pages). Keep it a named export so
`docs/image-handling.md` §4's "Staged local previews" pointer stays valid.

## 3. Barcodes on `/receipts`

`ManualReceiptDialog` needs `defaultCurrency` (`useAuth().user?.defaultCurrency ?? 'USD'`) and
the user's OUT categories. Mount it only while open (as the transaction form does) and load the
categories through `useCategories().fetchAll(signal)` (filtered to `direction !== 'IN'`) in a
`useAsyncOperation({ scope: 'control' })` started when the dialog opens; `onCreated` →
`router.push('/receipts/<id>')`. If the page cannot get categories without a provider the layout
lacks, report it instead of adding a provider.
