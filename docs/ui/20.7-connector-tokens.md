# 20.7 — Connector tokens UI

> Iteration 20.7 of [`phase-20-accounts-design.md`](../phase-20-accounts-design.md) (§3.5 "security
> first, automation second", §6.4 "Connector token"); plan row 20.7.
> Builds on the 20.1 kit (`Dialog`, `Card`, `Badge`, `EmptyState`, `PageHeader`, `Stat`, `Select`,
> `Input`, `Checkbox`) and on [`20.5-statement-import-review.md`](./20.5-statement-import-review.md).
> Binding: `docs/ui-async-conventions.md`, `docs/ui-realtime-conventions.md`, `wiki/ui-design-system.md`.

## 0. Shared contract

| Thing     | Value                                                                                                                                                                                               |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| API (JWT) | `POST /auth/tokens` `{ name, scopes?, expiresAt? }` → `{ id, name, scopes, token, createdAt, expiresAt }`; `GET /auth/tokens` → list **without** secrets; `DELETE /auth/tokens/:id` → 204           |
| Client    | `lib/auth/use-api-tokens.ts` — a hook, not a provider (the `useLlmApi` precedent: one settings surface, no cross-page cache); `listTokens`, `createToken`, `revokeToken`, each taking `AbortSignal` |
| Types     | `lib/auth/types.ts` gains `ApiTokenSummary` (`id,name,scopes,lastUsedAt,expiresAt,createdAt`) and `ApiTokenCreated` (`= ApiTokenSummary & { token: string }`)                                       |
| Scope     | `accounts:import` only — the token can do exactly one thing: `POST /accounts/:id/imports`. Rendered as a fixed `Badge tone="primary"`, never an editable control                                    |
| Reach     | The token acts **as the user**: it can import into any account the user may import into today, including group accounts where they are a member. Stated in the create dialog and on Help            |
| Cap       | 10 active tokens; `409 API_TOKEN_LIMIT_REACHED`                                                                                                                                                     |
| Secret    | The raw `mfp_…` value exists in the browser only for the lifetime of the reveal panel — never in state after `Done`, never in a URL, a log, a toast or an analytics call                            |
| Dates     | `formatOccurredAt` for created / last used, `formatOccurredDate` for expiry; every one inside `<span dir="ltr">`                                                                                    |
| Realtime  | **None.** No SSE event exists for tokens (nothing in the realtime doc's domain list) and none is added; freshness comes from the explicit `Refresh` control below                                   |

## 1. `/settings/tokens` — the surface

**Purpose.** "I want the connector on my laptop to push my bank lines into the app, and I want to be
able to cut it off in one click."
**User story.** _As a user, I can import my statements securely_ (design §1) — this is the second,
optional channel behind the manual import.
**Primary action.** `New token`. Every other control is secondary; `Revoke` is destructive.

**Route.** `app/[locale]/settings/tokens/{page.tsx,tokens-client.tsx}` — server shell
`<ProtectedRoute><TokensClient/>` plus the `settings/categories` client shell verbatim: `<main
className="container mx-auto max-w-3xl space-y-6 px-4 py-8" data-testid="tokens-page">`, one
`<PageHeader>`, mount-only initial fetch through `useAsyncOperation({ scope: 'page' })`,
`useResetOnLocaleChange`, failure → `<RetryReturnDialog>` returning to `/settings/account`.

**Entry points.** (a) a `Card` link at the end of `/settings/account` (`settings.tokens.entryTitle`
/ `…entryBody`) — settings has no index page, so sub-pages are reached from there; the twin link to
`/settings/categories` is missing today and is added in the same row; (b) the `/accounts/[id]`
Imports tab footer link `settings.tokens.fromImports`, where the need actually appears.

| State                | Rendering                                                                                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| First load           | `<PageProgressBar>` (page scope) + 3 pulse rows, `role="status"`, `aria-label` `settings.tokens.loading`, `tokens-loading`                |
| Refresh              | `<LoadingOverlay>` over `tokens-content` via `useAsyncOperation({ scope: 'container', id: 'tokens-refresh' })`; `New token` stays enabled |
| Error (initial)      | `<RetryReturnDialog>` (page-owned, newest-fetch guard)                                                                                    |
| Error (refresh/row)  | `<InlineErrorBanner>` above the list with Retry — never a modal for a control-scope failure                                               |
| Empty                | `<EmptyState>` — §2                                                                                                                       |
| Populated            | `<ul className="space-y-2">` of `<Card as="li">` rows (§3), newest first; no pagination (cap 10)                                          |
| Limit reached (= 10) | `New token` `disabled` + `aria-disabled`, hint line `settings.tokens.limitHint`; the `Stat` turns `tone="warning"`                        |
| Expired rows         | `Badge tone="danger"` `settings.tokens.expired`, card `muted`; still revocable                                                            |
| Permission           | Personal only — tokens belong to the signed-in user; there is no group view and no owner/member split on this page                        |

Header block: `<Stat label={settings.tokens.active} value="{count} / 10" />` plus a `Refresh`
`Button variant="outline" size="sm"` (`tokens-refresh`) — the only way to a fresh `lastUsedAt`,
which is how a user confirms the connector really ran.

## 2. Empty state (the one paragraph that sets expectations)

`<EmptyState title={settings.tokens.emptyTitle} description={settings.tokens.emptyBody}
action={New token}>` with a second line `settings.tokens.emptyPreferImport` rendered as a link to
`/accounts` ("Import a statement instead").

> **emptyBody (English source).** "A connector token lets a small program you run on your own
> computer push your bank lines into MyFinPro. Your bank password stays on your machine — it is never
> sent here, and this token can do nothing except add statement lines to your accounts. Revoke it any
> time and the connector stops. For most people the simpler path is still to download a statement and
> import it in the app; set up a connector only if you want it automatic."

## 3. Token row (`components/settings/ApiTokenRow.tsx`)

`Card as="li"`, two zones:

- **Row 1** — name (`font-medium`, truncate, `title` fallback) · `Badge tone="primary"`
  `settings.tokens.scopes.accountsImport` ("Import statement lines") · expiry badge
  (`neutral` "No expiry" / `warning` "Expires {date}" within 14 days / `danger` "Expired").
- **Row 2** — muted meta: `settings.tokens.created` `{date}` · `settings.tokens.lastUsed` `{date}`
  or `settings.tokens.neverUsed`, each date in a `dir="ltr"` span.
- **End** — one `Button variant="danger" size="sm"` `Revoke` (`token-revoke-<id>`); a single action,
  so no `RowActionsMenu` (20.3's ⋮ exists because accounts have four).

`Revoke` opens `ConfirmDialog danger`: title `settings.tokens.revoke.title`, message
`settings.tokens.revoke.warning` — _"Revoke "{name}"? Any connector using it stops working
immediately. Lines it already imported are kept."_ Confirm runs one shared
`useAsyncOperation({ scope: 'control', id: 'token-revoke' })` (`ButtonSpinner` inside the dialog's
confirm, `busy` on the dialog); on 204 the row is removed from local state, success toast
`settings.tokens.revoke.done`; on failure the dialog keeps the inline banner and the row stays.

## 4. `CreateApiTokenDialog` — two panels in one `Dialog size="md"`

Panel A is the form; Panel B is the show-once reveal. They are panels of the same dialog (the
secret must not survive a navigation), with `Dialog busy` while the create op runs.

### Panel A — form

| #   | Field  | Control                                                                                                                             |
| --- | ------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Name   | `Input`, required, ≤ 60, autofocus, placeholder `settings.tokens.form.namePlaceholder` ("Laptop connector")                         |
| 2   | Expiry | `Select`, options `90` (default) / `30` / `365` days / `never`; converted to an ISO `expiresAt` at submit, `never` omits the field  |
| 3   | Scope  | read-only line: the fixed `Badge` + `settings.tokens.form.scopeFixed` ("Import statement lines — this is all a token can ever do.") |

Under the fields, `settings.tokens.form.reach` (the "acts as you" note) as muted text. Submit =
`useAsyncOperation({ scope: 'control', id: 'token-create' })`; `API_TOKEN_LIMIT_REACHED` →
`InlineErrorBanner` (`…form.limitError`) with the primary disabled, validation → field errors,
anything else → `…form.errorGeneric`. Closing Panel B is always allowed but passes through
`settings.tokens.reveal.closeConfirm` (a non-`danger` `ConfirmDialog`).

### Panel B — the show-once reveal

Replaces the form in place on success (no route change, no remount of the dialog):

1. `role="alert"` warning strip, id `token-reveal-warning`: `settings.tokens.reveal.warning` —
   _"Copy this token now. It will not be shown again — if you lose it, revoke it and create a new one."_
2. `<CopyField>` (§6) with the raw token: a **read-only `<input>`**, `dir="ltr"`, `spellCheck={false}`,
   `aria-describedby="token-reveal-warning"`, `onFocus` selects all, and a `Copy` button.
3. `settings.tokens.reveal.next` heading + the **command block**: a second `<CopyField multiline>`,
   value exactly two lines, `dir="ltr"`, monospace, `whitespace-pre`, `overflow-x-auto` on phone:

   ```
   npx @myfinpro/connector init
   npx @myfinpro/connector sync
   ```

   Its `Copy` copies both lines. Under it, `settings.tokens.reveal.initHint`: _"`init` asks for this
   token and your MyFinPro address once and stores them in the connector's own config on your
   computer. Paste the token when it asks — never type it into the command itself."_ (never a CLI
   argument: shell history). Then `settings.tokens.reveal.syncHint`: _"`sync` signs in to your bank
   on your machine, reads the new lines and sends only those lines here. Run it whenever you like,
   or from your own scheduler."_ Then a link to `/help#connector` and to the account's Review tab
   (`settings.tokens.reveal.reviewHint` — imported lines still wait for a decision, 20.5).

4. Footer: primary `Done` (`token-reveal-done`) — closes, drops the secret from state, prepends the
   new row to the list (from the create response, never from a refetch).

## 7. Realtime

Nothing. Tokens are single-user, low-frequency data and the SSE bus carries no `api-token.*` event;
none is added. `lastUsedAt` freshness is explicit (`Refresh`, container scope), so this page does
**not** call `useRealtimeEvents`/`useRealtimeResync` — deliberate, not an omission.

**Hebrew notes.** אסימון (token) is masculine — phrase created/revoked/expired to agree; שורה
(statement line) is feminine, as in 20.5. The token value, the `npx …` lines, the app URL, `mfp_…`,

## 9. Accessibility

- `PageHeader` renders the single `<h1>`; the page owns `<main id="main-content">`; rows are `<li>`
  labelled by the token name.
- Focus order: skip link → sidebar → `New token` → `Refresh` → row 1 name → row 1 `Revoke` → …
- Create flow: opening the dialog focuses Name; on success focus moves to the revealed token input
  (which selects its content, warning as its `aria-describedby`); `Done` restores focus to
  `New token`. Revoke returns focus to the next row's `Revoke`, or to `New token` when the list
  empties. Kit `Dialog` provides the trap, ESC, backdrop and scroll lock.
- Copy feedback is a polite `role="status"` line inside `CopyField` ("Copied" / "Press Ctrl+C to
  copy") rather than only a toast; the clipboard failure path selects the text and says so.
- Control-scope buttons carry `disabled` **and** `aria-busy` in flight; the reveal warning is
  `role="alert"` and the limit hint is tied to the disabled button by `aria-describedby`.
- Colour is never the only signal: the expiry badge prints its date or the word "Expired"; the
  scope badge prints the scope. Both themes get explicit `dark:` variants — check the read-only
  token field (muted background + monospace) and the amber "expiring soon" badge in dark mode, the
  recurring dark-mode fix.

## 11. Connector docs page

The user-facing explanation lives on the **existing Help page** (`app/[locale]/help/page.tsx`,
server-rendered sections from the `help.*` namespace) as a new numbered section
`help.connector.*`, inserted before "Getting Help" and anchored `#connector`; the reveal panel and
the Help link both point there. The developer/CLI reference stays in `apps/connector/README.md`
(repo, not the app) and the security rationale in the design doc §3.5 — one owner per fact.

One screen, four cards in the Help page's existing card style:

1. **What a connector is** — a program you run on your own computer; the app never learns your bank
   password; compare in one line with the statement import and say the import is the recommended
   default.
2. **Set it up** — create a token in Settings → Connector tokens (link), install Node, run
   `npx @myfinpro/connector init` (paste the token and the app address when asked), then `sync`.
3. **What happens to the lines** — they land as a normal import; you review and accept them in the
   account's Review tab exactly like a file import (links to `/accounts`).
4. **Staying safe** — one token per machine, an expiry, revoke instantly from settings, and what to
   do if a token leaks (revoke, create a new one, run `init` again).
