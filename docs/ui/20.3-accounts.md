# 20.3 — Accounts UI

> Iteration 20.3 of [`phase-20-accounts-design.md`](../phase-20-accounts-design.md) (§2, §6.1, §6.3, §7).
> Prerequisite: the 20.1 kit — `Dialog`, `Select`, `Textarea`, `Checkbox`, `Card`, `Badge`,
> `PageHeader`, `EmptyState`, `Tabs`, `Stat`. Every surface below is a composition of those plus
> `components/ui/*`; no new shell. Import and review surfaces: [`20.5-statement-import-review.md`](./20.5-statement-import-review.md).
> Binding: `docs/ui-async-conventions.md`, `docs/ui-realtime-conventions.md`, `wiki/ui-design-system.md`.

## 0. Shared contract

| Thing            | Value                                                                                                                                                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client           | `lib/account/account-context.tsx` (budget-context shape): `fetchAccounts`, `fetchAccount`, `createAccount`, `updateAccount`, `archiveAccount`, `unarchiveAccount`, `deleteAccount` — every call takes an `AbortSignal` |
| Types            | `lib/account/types.ts` re-exporting `AccountSummary` (= `AccountResponseDto`), `CreateAccountInput`, `UpdateAccountInput`, `ListAccountsParams`                                                                        |
| Can manage       | `scopeType === 'personal' \|\| group.role === 'admin'` (the `BudgetCard` rule). A group **member** sees the card and `Import statement`, but no ⋮ menu                                                                 |
| Money            | `formatAmount` / `formatSignedAmount`; typed input → `parseAmountToCents` (accepts a leading `-`). Never `toFixed`                                                                                                     |
| Dates            | `formatOccurredDate` for display; `<input type="date">` + `localInputToIso` for editing                                                                                                                                |
| Labels           | kind → `accounts.kinds.<BANK\|CARD\|CASH\|OTHER>`; institution → `INSTITUTION_META[x].name` (proper noun, not translated); scope chip → `formatScopeLabel` (existing)                                                  |
| Balance polarity | ledger < 0 on a `CARD` renders as **owed** (`accounts.card.owed`, `Stat tone="warning"`), never as a negative debt figure (design §2.4)                                                                                |

## 1. `/accounts` — list page

**Purpose.** "Where is my money, and does the app agree with the bank?" — the user registers
accounts, sees each balance and whether anything is waiting to be reconciled.
**Primary action.** `New account`. Secondary: `Import statement`.
**Entry points.** Sidebar → Accounts; dashboard `AccountsOverview` → `Manage accounts`; the account
chip on a transaction row/detail → `/accounts/[accountId]`.

| State             | Rendering                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| First load        | 4 pulse placeholders, `role="status"`, `aria-label` `accounts.list.loading` — `accounts-loading` (budgets pattern) |
| Refresh / filters | `<LoadingOverlay active>` over `accounts-content`; every control `disabled` while in flight                        |
| Error             | `<RetryReturnDialog>` owned by the page (newest-fetch guard: a superseded SSE refetch must not open it)            |
| Empty (no filter) | `<EmptyState>` title `accounts.list.emptyTitle`, description `…emptyBody`, action = `New account`                  |
| Empty (filtered)  | `<EmptyState>` description `accounts.list.emptyFiltered` (no action)                                               |
| Populated         | `<Card>` per account in a `<ul>`; cursor `Load more` (limit 20)                                                    |
| Archived rows     | `muted` card + `Badge tone="neutral"` `accounts.list.archivedChip`; only visible when the toggle is on             |
| Member (no admin) | card renders identically minus `account-actions-<id>`; `Import statement` stays enabled                            |

**Async scopes.** `useAsyncOperation({ scope: 'container', id: 'accounts-page-fetch' })` for the
list and `Load more`; one shared `{ scope: 'control' }` op for archive/unarchive (`accounts-archive`)
and one for delete (`accounts-delete`) — failures → error toast, per the budgets page.

**Layout.**

| Breakpoint      | Layout                                                                                                                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Phone (base)    | one column, `PageHeader` actions wrap under the title; card body stacks: title row, meta chips row, `Stat` row, footer badges; ⋮ stays on the title row, end-aligned and thumb-reachable |
| Tablet (`sm:`)  | header actions inline with the title; `Stat`s side by side inside the card                                                                                                               |
| Desktop (`md:`) | `md:grid-cols-2` of cards, max width `max-w-5xl`                                                                                                                                         |

**Card anatomy** (`components/account/AccountCard.tsx`, mirrors `BudgetCard`):
row 1 — name (truncate) · `Badge` kind · `Badge tone="neutral"` institution · `last4` as `·· 1234`
(`<span dir="ltr">`) · `RowActionsMenu`; row 2 — scope chip · archived chip;
row 3 — `<Stat label={accounts.card.ledger} value={formatAmount(ledgerBalanceCents…)} hint={as of …} />`
and, when `reportedBalanceCents !== null`, `<Stat label={accounts.card.reported} hint={asOf} />`;
row 4 — gap badge (`reconciliationGapCents === 0` → tone `success`, `accounts.card.reconciled`;
non-zero → tone `warning`, `accounts.card.gap` `{amount}`) and, when `pendingLinesCount > 0`, a
`Badge tone="warning"` **link** to `/accounts/[id]?tab=review` reading `accounts.card.pending`.

**Row actions** (`RowActionsMenu`, `triggerLabel` = `accounts.list.actions`): `Edit` (disabled when
archived), `Import statement`, `Archive`/`Unarchive`, `Delete` (destructive).

## 2. `AccountFormDialog` (create / edit)

Composition: `Dialog size="md"` + `Input` + `Select` + `TransactionScopeSelector` +
`AccountSelect` + `Button`/`ButtonSpinner`/`InlineErrorBanner`. Save =
`useAsyncOperation({ scope: 'control', id: 'account-form-save' })`; transport failures → inline
banner with Retry; domain errors map to fields. Dirty close → the budgets discard prompt.

| #   | Field            | Control                     | Rules                                                                                                                                |
| --- | ---------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Name             | `Input`                     | required, ≤ 100                                                                                                                      |
| 2   | Kind             | `Select`                    | `ACCOUNT_KINDS`; changing it re-filters field 3 and clears an incompatible institution                                               |
| 3   | Institution      | `Select`                    | `ACCOUNT_INSTITUTIONS.filter(i => INSTITUTION_META[i].kinds.includes(kind))`, plus an empty `accounts.form.institutionNone`          |
| 4   | Currency         | `Select`                    | `CURRENCY_CODES`, default `user.defaultCurrency`; **edit mode**: read-only text + `accounts.form.currencyImmutable`                  |
| 5   | Scope            | `TransactionScopeSelector`  | single selection (`value={scope ? [scope] : []}`); **edit mode**: disabled + `accounts.form.scopeImmutable`                          |
| 6   | Last 4 digits    | `Input inputMode="numeric"` | optional, `ACCOUNT_LAST4_PATTERN`; hint `accounts.form.last4Hint` ("Last digits only — never the full number")                       |
| 7   | Opening balance  | `Input inputMode="decimal"` | `parseAmountToCents`, may be negative; paired with **Opening balance date** (`<input type="date">`, required when the amount is set) |
| 8   | Billing account  | `AccountSelect`             | **CARD only**; `kinds={['BANK']}`, `currency` and scope fixed to the form's; empty = none                                            |
| 9   | Billing day      | `Select` 1–28               | **CARD only**, enabled only when field 8 is set; hint `accounts.form.billingHint`                                                    |
| 10  | Reported balance | `Input` + date              | **edit mode only**; hint `accounts.form.reportedHint` ("The bank's own number — statement imports update it for you")                |

Domain-error → field map: `ACCOUNT_INVALID_SCOPE`→scope, `ACCOUNT_CURRENCY_MISMATCH`→currency,
`ACCOUNT_INVALID_BILLING`→billing account, anything else → the inline banner with
`accounts.form.errorGeneric`.

## 3. `AccountSelect` — the one account picker

`components/account/AccountSelect.tsx`. Wraps the kit `Select`; self-fetches when no `accounts`
prop is given, through `useAsyncOperation({ scope: 'container', id: 'account-select-fetch' })`
(`TransactionCategoryPicker` pattern: `<LoadingOverlay>` + `InlineErrorBanner` with Retry).

| Prop                                | Meaning                                                               |
| ----------------------------------- | --------------------------------------------------------------------- |
| `value: string \| null`             | selected account id; `''` ⇒ `onChange(null)`                          |
| `onChange(id: string \| null)`      | —                                                                     |
| `currency?: string`                 | only accounts with this currency are listed (design §6.3)             |
| `kinds?: AccountKind[]`             | e.g. `['BANK']` for the billing account                               |
| `scope?: AttributionScope`          | restrict to one scope (billing account, line-decision defaults)       |
| `excludeIds?: string[]`             | the transfer source excludes itself                                   |
| `includeArchived?: boolean`         | default `false`; an archived account already set stays listed, marked |
| `emptyOptionLabel?: string`         | default `accounts.select.unplaced` ("No account")                     |
| `accounts?`, `disabled?`, `testId?` | `testId` default `account-select`                                     |
| `label?`, `error?`                  | forwarded to `Select`                                                 |

Options are `<optgroup>`s by scope (Personal → each group, `formatScopeLabel`); an option's text is
`name · INSTITUTION_META.name · ·· last4` with the digits in a `dir="ltr"` span. Consumers:
`TransactionFormDialog` (new optional field, immediately after Currency), `TransactionsFilters`
(new `accountId` filter, after Category), the transfer destination, `AccountFormDialog` field 8, and
the 20.5 review rows.

## 4. Transfer entry in `TransactionFormDialog`

A `Checkbox` `accounts.transfer.toggle` ("This is a transfer between my accounts") sits directly
under the Account field. When checked:

- the Direction group and the Categories block are **hidden** (not merely disabled) — direction is
  forced `OUT` and the primary category is the system `transfer` category, set by the form;
- a second `AccountSelect` appears, labelled `accounts.transfer.to`, with
  `currency={state.currency}` and `excludeIds={[accountId]}`;
- the Account field becomes required and is relabelled `accounts.transfer.from`;
- a one-line hint `accounts.transfer.hint` ("Transfers never count as spending.") renders under the pair;
- validation: both set, distinct, same currency → else `accounts.transfer.validation.*`;
  `TRANSACTION_TRANSFER_INVALID` from the API → the `transfer.to` field error.

Unchecking restores direction/categories with the previous values. In edit mode the toggle is
pre-checked when `transferAccountId !== null`.

## 6. Dashboard `AccountsOverview`

`components/dashboard/AccountsOverview.tsx`, mounted between `<TotalsCard>` and
`<ScopeEntryCards>`, re-mounted by the dashboard `refreshKey` like its siblings.
Fetch: `useAsyncOperation({ scope: 'container', id: 'dashboard-accounts-fetch' })`, non-archived only.

- Header: `accounts.overview.title` + link `accounts.overview.manage` → `/accounts`.
- Net position per currency as `<Stat>` (sum of ledger balances, `Σ` of that currency's accounts),
  sorted with `user.defaultCurrency` first (the `TotalsCard` rule).
- Then one compact row per account: name · kind badge · ledger amount (`dir="ltr"`, `text-end`).
- When `Σ pendingLinesCount > 0`, a nudge line `accounts.overview.pending` (ICU plural, with the
  unexplained gap amount when any account reports one) linking to that account's `?tab=review`.
- States: loading `role="status"`; error → `InlineErrorBanner` + Retry (widget-local, never a dialog);
  empty → `<EmptyState>` `accounts.overview.empty` with a `New account` action opening the form dialog.

## 7. Sidebar

New `NAV_ITEMS` entry **between** `/transactions` and `/budgets`: `href: '/accounts'`,
`labelKey: 'nav.accounts'`, Heroicons outline `wallet` path. Nothing else changes; `aria-current`
and the focus ring come from the existing item renderer.

## 8. Delete confirmation

`ConfirmDialog` (`danger`), title `accounts.delete.title`, message `accounts.delete.warning`:
_"Delete "{name}"? Its transactions are kept and become unplaced; imported statements and their
lines are deleted. This can't be undone."_ Confirm runs the `accounts-delete` control op; on success
the row drops out and a success toast fires.

## 9. Realtime

| Event                                   | Where              | Handling                                                            |
| --------------------------------------- | ------------------ | ------------------------------------------------------------------- |
| `account.updated`                       | `/accounts`        | refetch the committed first page (advisory; payload is only the id) |
| `account.updated`                       | `AccountsOverview` | refetch the widget                                                  |
| `transaction.created/.updated/.deleted` | `/accounts`        | refetch — balances are derived from transactions                    |
| resync (`useRealtimeResync`)            | both               | same refetch as above                                               |

Every subscribing view calls **both** `useRealtimeEvents` (one hook per type, narrowest filter) and
`useRealtimeResync`. Mutations still update state from their own HTTP response, never from the echo.

## 11. Accessibility

- `PageHeader` renders the single `<h1>`; the page owns `<main id="main-content">`. Card = `<li>` with
  the name as its accessible label; the ⋮ trigger is a `<button>` labelled `accounts.list.actions`
  and `RowActionsMenu` stays portalled.
- Focus order on the list: skip link → sidebar → `New account` → `Import statement` → scope tabs →
  archived toggle → first card link → its ⋮. Tabs are `role="tab"` inside `role="tablist"`
  (kit `Tabs`), arrow keys move between them, Home/End jump.
- Dialog: `role="dialog" aria-modal`, focus trapped, focus restored on close, ESC + backdrop close,
  body scroll locked (all inherited from kit `Dialog` — do not re-implement).
- Every control-scope button sets `disabled` **and** `aria-busy` while saving.
- Badges are text, not colour-only: the gap badge always prints the amount, `Reconciled` prints the
  word. Both themes carry explicit `dark:` variants; check the warning badge's contrast in dark mode.
