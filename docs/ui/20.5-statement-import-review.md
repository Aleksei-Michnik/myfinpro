## 0. Shared contract

| Thing          | Value                                                                                                                                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client         | `lib/account/account-context.tsx` gains `createImport`, `fetchImports`, `fetchLines`, `matchLine`, `createFromLine`, `transferFromLine`, `ignoreLine`, `unlinkLine`, `applySuggestions` — all `(…, signal)` |
| Parsing        | `lib/statement/decode.ts` (`File` → `string[][]`, CSV `windows-1255`/UTF-8, XLSX/XLS) → `parseStatementRows` from `@myfinpro/shared`. **Nothing binary leaves the browser**                                 |
| Untrusted text | `description`, `memo`, `categoryHint` render as text (never `dangerouslySetInnerHTML`), truncate with a `title` fallback                                                                                    |
| Numbers        | `formatSignedAmount(amountCents, direction, currency, locale)`; every amount, date and `last4` sits in a `dir="ltr"` span so RTL cannot reorder it                                                          |
| Roles          | Any owner **or group member** may import and decide lines (design §2.1). Non-accessors never reach the route (404 → `RetryReturnDialog` "no access" path)                                                   |

## 1. `ImportStatementDialog` — 3 steps

**Purpose.** Turn a statement the user downloaded from their bank into reviewable lines without the
file ever leaving the device. **Primary action per step:** `Continue` → `Import N lines` → `Review N lines`.
**Entry points.** `/accounts` header `Import statement`, the card's ⋮ → `Import statement`
(account pre-selected and locked), `/accounts/[id]` header button.

Shell: kit `Dialog size="lg"`, `busy` while an op runs; a step indicator (`1 · 2 · 3`,
`aria-current="step"`), `Back` on steps 2–3 (step 3 `Back` is hidden — the import already landed).

### Step 1 — account + file

| Element      | Spec                                                                                                                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account      | `AccountSelect` (`includeArchived={false}`), disabled when pre-selected; label `accounts.import.account`                                                                                          |
| Drop zone    | a labelled `<div>` with `onDragOver/onDrop` wrapping `FileCaptureButtons` (`accept=".csv,.xlsx,.xls"`, `multiple={false}`, `testIdPrefix="statement"`, ref → `openPicker()` on click/Enter/Space) |
| Privacy note | `accounts.import.privacy`: "Parsed in your browser — the file is never uploaded. Only the parsed lines are sent."                                                                                 |
| Errors       | unsupported type / >10 MB / unreadable → `InlineErrorBanner` (`accounts.import.errors.*`), the zone stays usable                                                                                  |

Parsing runs through `useAsyncOperation({ scope: 'control', id: 'statement-parse' })` (`ButtonSpinner`
on Continue; decoding a large XLSX is not instant).

### Step 2 — preview

| Element         | Spec                                                                                                                                                                                                                                                                                                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Detected preset | `Badge tone="success"` `accounts.import.preset` `{name}` (`generic_csv` → tone `neutral`); then three `Stat`s: rows, date range (`periodFrom`–`periodTo`), statement balance (omitted when absent)                                                                                                           |
| Sample          | first **5** parsed lines as a mini table (date · description · amount) — `md:` table, phone: stacked rows                                                                                                                                                                                                    |
| Warnings        | `parseStatementRows().warnings[]` as a `Card muted` list, `role="status"` — informational, never blocking                                                                                                                                                                                                    |
| Manual mapping  | shown when detection failed **or** the user clicks `accounts.import.remap`: one `Select` per target (date, amount **or** debit+credit, description, balance, reference) whose options are the real header cells (`Column {index}: {header}`) plus "—". Re-parses on every change (same `statement-parse` op) |
| Blocking        | `Import` is disabled while date or amount is unmapped, or when 0 lines parsed (`accounts.import.errors.noRows`), or `lines.length > ACCOUNT_IMPORT_MAX_LINES` (`…tooLarge`)                                                                                                                                  |

### Step 3 — result

`POST /accounts/:id/imports` via `useAsyncOperation({ scope: 'control', id: 'statement-import-submit' })`;
`ACCOUNT_IMPORT_TOO_LARGE` / `…INVALID_LINE` → inline banner with the server's line index, Back stays available.

Counters from `AccountImportResponseDto` as a `Stat` grid (inserted, duplicates skipped, confident
matches, transfer proposals, needs input), then:

- primary `accounts.import.reviewCta` — `Review {count} lines` → `/accounts/[id]?tab=review`;
- secondary `accounts.import.applyCta` — `Apply {count} confident suggestions`, inline, via
  `useAsyncOperation({ scope: 'control', id: 'statement-apply-suggestions' })`; counters update in place;
- `Done` closes and refreshes the host surface.

Zero-insert case: `EmptyState` `accounts.import.allDuplicates` ("Nothing new — every line was already imported.").

## 2. `/accounts/[accountId]` — shell

`PageHeader` title = account name, description = kind · institution · `·· last4`,
actions = `Import statement`, `Edit` (manage-only), `RowActionsMenu`.
Three `Stat`s: ledger balance (`accounts.card.ledger`), reported balance + as-of date, gap
(tone `success` at 0, `warning` otherwise — always with the amount in text).
Fetch: `useAsyncOperation({ scope: 'container', id: 'account-detail-fetch' })`; failure →
`RetryReturnDialog` (Return → `/accounts`).

Kit `Tabs`, URL-synced through `?tab=review|transactions|imports` (`useSearchParams` read on mount;
`router.replace` written **only after** the tab's first fetch commits — the committed-filter rule).
Default tab: `review` when `pendingLinesCount > 0`, else `transactions`. The Review tab label carries
the pending count as a `Badge`.

## 3. Review tab — the pending-lines queue

**Purpose.** Decide what each bank line means, one row at a time, fast, resumable, reversible.
**Primary action.** Accept the suggestion (Enter).

| State           | Rendering                                                                                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Loading (first) | 5 pulse rows, `role="status"`, `accounts.review.loading`; refresh → `<LoadingOverlay>` over the queue, filters disabled while in flight                                              |
| Error           | `RetryReturnDialog` (page-owned) for the list; a **row** decision failure → `InlineErrorBanner` inside that row + the row stays put                                                  |
| Populated       | `<ul role="list">` of rows, cursor `Load more` (limit 25)                                                                                                                            |
| Empty           | gap = 0 → `EmptyState` `accounts.review.emptyReconciled` (the reward, tone success); gap ≠ 0 → `…emptyGap` `{amount}`; never imported → `…emptyNoImport` + action `Import statement` |

Fetch: `useAsyncOperation({ scope: 'container', id: 'account-lines-fetch' })`. One shared
`{ scope: 'control', id: 'statement-line-decide' }` op for match/create/transfer/ignore,
`{ scope: 'control', id: 'statement-line-undo' }` for `DELETE …/link`, and the
`statement-apply-suggestions` op for the bulk bar.

**Toolbar.** Filter as a kit `Tabs` (segmented): `all` (pending) · `needsInput`
(`suggestion.action === 'none'` or `create` with no category) · `suggested` · `decided`
(`status != PENDING`, so an undo is reachable after the toast is gone). Right of it, the bulk button
`accounts.review.applyAll` `Apply {count} confident suggestions` (disabled at 0; a
`ConfirmDialog` guards counts > 20).

**Undo.** A decided row leaves the list with a success toast **and** an inline
`accounts.review.undoBar` strip pinned under the toolbar: "{description} — {decision}" + `Undo`
(calls `unlinkLine`, reinserts the row at its date position). The strip holds the last decision only;
older ones are undone from the `decided` filter, which shows an `Undo` action per row.

### Row anatomy (`StatementLineCard`)

| Zone        | Content                                                                                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Head        | `postedAt` (and `valueAt` as `accounts.review.valueAt` when different) · description (bold, truncate) · signed amount, end-aligned, `dir="ltr"`            |
| Meta badges | memo (muted) · `Badge` installment `{n}/{total}` · `Badge` original amount `{amount} {currency}` when `originalAmountCents` · `Badge muted` `categoryHint` |
| Suggestion  | one of the four blocks below, rendered as the **default action**                                                                                           |
| Actions     | primary `Accept` (control op, `ButtonSpinner`) · `Skip` (moves the cursor, decides nothing) · `Ignore` (always available, `Badge`-styled ghost button)     |

| Suggestion              | Block                                                                                                                                                                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `match`                 | `Card muted` with the candidate: date · primary category · amount · note (truncate) + `accounts.review.chooseAnother` opening a `Dialog size="sm"` listing the other `suggestion.candidates` ranked, each with a percent `Badge`, selectable with ↑/↓ + 1–9 + Enter |
| `transfer`              | `accounts.review.transferTo` + `AccountSelect` (`currency` = line currency, `excludeIds=[accountId]`) pre-set to `suggestion.transferAccountId`; the `→` icon mirrors under RTL                                                                                     |
| `create`                | `accounts.review.createAs` + `TransactionCategoryPicker` (`direction` = line direction) pre-set to `suggestion.categoryId`; scope chip = the account's scope, `accounts.review.changeScope` reveals `TransactionScopeSelector`                                      |
| `create`, null category | the same block with `Badge tone="warning"` `accounts.review.needsCategory` ("Needs a category"); `Accept` disabled until one is chosen; bulk apply skips these rows                                                                                                 |
| `none`                  | falls back to the `create` block with no preselection, plus the `needsCategory` badge                                                                                                                                                                               |

Changing the control inside a block switches the row's action away from the suggestion; `Accept`
then calls the corresponding endpoint (`match` / `transfer` / `create` / `ignore`).

**Layout.** Phone: one card per line, full width, `Accept` full-width at the bottom of the card so it
is thumb-reachable; `Skip`/`Ignore` side by side above it; the suggestion control stacks. `md:`: the
head becomes one line (date · description · amount), the suggestion block sits on the start side and
the action buttons end-aligned on the same row. `lg:`: queue `max-w-4xl`, the toolbar sticks to the
top of the scroll container (`sticky top-0`) so the bulk bar is always reachable. No swipe gestures —
the app uses swipe only in `DocumentViewer`/carousels, and a destructive decision must not be a swipe.

## 4. Keyboard model (mirrors `ItemWalkthroughDialog`)

Queue container `role="list"` + `aria-label` `accounts.review.queueLabel`, roving `tabIndex` on rows
(active row `tabIndex=0` + `aria-current="true"`, scrolled into view); a `role="status" aria-live="polite"`
line announces "{position} of {count} · {description}". Keys are handled on the container and ignored
while a text input inside the row has focus (walkthrough's `inSearch` guard):

| Key             | Action                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `↓` / `↑`       | next / previous line                                                                                                            |
| `→` / `←`       | same, direction-corrected with `arrowKeyDelta(el, key)` from `lib/swipe.ts`                                                     |
| `Enter`         | Accept the row's current action                                                                                                 |
| `M` / `C` / `T` | switch the row to Match (opens the candidate picker) / Create (focus the category picker) / Transfer (focus the account select) |
| `I` / `S` / `U` | Ignore this line / Skip — decide nothing / Undo the last decision                                                               |
| `1`–`9`         | inside the candidate picker: pick that candidate                                                                                |
| `Esc`           | leave the queue — focus returns to the filter tabs (inside the picker: close it)                                                |

Shortcuts are listed once under the toolbar in a `<details>` `accounts.review.shortcuts`, and each
action button carries `aria-keyshortcuts`.

## 5. Transactions tab

`<TransactionsList>` in self-fetch mode with `filters={{ ...defaultFilters, accountId }}`,
`lockScope`, `showFilters` (account filter hidden — it is fixed by the page, via
`hide={{ scope: true, account: true }}`). Transfers stay visible here (no `excludeTransfers`), and
rows carry the `row-transfer-<id>` and `row-bank-confirmed-<id>` badges from 20.3 §5. Empty state:
`accounts.detail.noTransactions`.

## 6. Imports tab

`useAsyncOperation({ scope: 'container', id: 'account-imports-fetch' })`, cursor list. Phone: one
`Card` per import; `md:`: a table — date · source (`accounts.import.sources.<source>`) · file name
(truncate, `dir="ltr"`) · rows/inserted/duplicates · statement balance.
Row click filters the Review tab by that import (`?tab=review&import=<id>`), shown as a removable
`Badge` in the review toolbar. Empty: `EmptyState` `accounts.detail.noImports` + `Import statement`.

## 7. Realtime

| Event                              | Effect                                                                                                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `account.updated`                  | refetch the detail header (`account-detail-fetch`) **and** the active tab's counts; the Review list refetches only when the tab is active                                       |
| `transaction.created` / `.updated` | refresh the review rows that reference that `transactionId` (replace-by-id; if the row is not on screen, ignore) — a match made in another tab must not leave a stale candidate |
| `transaction.deleted`              | the referencing row returns to `PENDING` on the server; refetch the queue page                                                                                                  |
| `useRealtimeResync`                | refetch header + active tab                                                                                                                                                     |

One hook per event type, handlers idempotent, no second `EventSource`. Decisions update local state
from their own HTTP response; the SSE echo only re-validates.

## 9. Accessibility

- Dialog behaviour (focus trap, restore, ESC, scroll lock, `aria-modal`) comes from kit `Dialog`; the
  step indicator is an `<ol>` with `aria-current="step"` and a step change moves focus to its heading.
- The drop zone is keyboard-operable: `tabIndex={0}`, `role="button"`, Enter/Space open the picker,
  and it is labelled by the format hint; drag-and-drop is never the only path.
- Review focus order: tab strip → filter tabs → bulk button → undo strip → first row → its controls;
  roving tabindex inside the queue; the active row and every decision result
  (`accounts.review.decided.*`) are announced in the polite status region.
- Buttons in flight carry `disabled` + `aria-busy`; the row's error banner is `role="alert"`.
- Colour is never the only signal: the gap `Stat`, the `needsCategory` badge, the match percentage
  and the warning list all print text. Check the warning/amber badge and the `Stat` hint text contrast
  in dark mode — the recurring dark-mode fix.

## 11. E2E flow — `apps/web/e2e/accounts.spec.ts`

Fixture `apps/web/e2e/fixtures/statement-generic.csv` — synthetic, 6 rows: 1 matching an existing
transaction, 1 card-bill line, 3 new purchases, 1 duplicate.

1. Create an account (`accounts-new` → `account-form-*` → `account-form-save`) with an opening balance.
2. Create a transaction on it (`transactions-list-add` → `form-account` → save).
3. `accounts-import` → `statement-import-account` → `statement-file-input` set to the fixture →
   `statement-import-continue`; assert `statement-import-preset` and `statement-import-rows`.
4. `statement-import-submit`; assert `statement-result-inserted` = 5, `statement-result-duplicates` = 1.
5. `statement-import-review-cta` → asserts `account-review-list` and `account-tab-review-count`.
6. Keyboard pass: focus the first row, `Enter` accepts the match, `C` + category + `Enter` creates,
   `T` + `Enter` records the transfer, `I` ignores one; each row leaves the list, `account-review-undo`
   appears, `U` brings the last one back.
7. `account-review-apply-all` for the rest; assert `account-review-empty` and `account-detail-gap`
   reading the reconciled string (gap = 0); `account-tab-transactions` shows the created rows with
   `row-bank-confirmed-*` and `row-transfer-*`.
